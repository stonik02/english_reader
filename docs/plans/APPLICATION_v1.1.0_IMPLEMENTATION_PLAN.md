# План реализации требований v1.1.0

Дата: 2026-09-04.

Этот план относится к дополнению
[`APPLICATION_v1.1.0.md`](../business_requirements/APPLICATION_v1.1.0.md).
Работы выполняются сверху вниз: последующий этап не начинается, пока не
пройдены критерии приёмки предыдущего.

## Граница версии

В v1.1.0 не меняется базовая архитектура: для семейного приложения с менее чем
50 пользователями остаётся один Go API, одна PostgreSQL БД, Envoy для gRPC-Web,
локальное файловое хранилище EPUB и LibreTranslate. Разделение на микросервисы,
Redis или внешнее объектное хранилище сейчас увеличит сложность без пользы.

Новые backend-запросы, если они понадобятся, должны соблюдать правило проекта:
`handler → request-specific usecase → optional service → repository`.

## 0. Контроль исходного состояния — в работе

Цель: проверить, что уже реализованные части действительно доступны в браузере,
а не только присутствуют в коде.

1. Проверить на новой EPUB-книге извлечение и показ обложки в общем и личном
   каталогах.
2. Проверить карточку перевода для обычной формы, неправильного глагола и
   регулярной формы: перевод, часть речи, пример и перевод контекстного
   фрагмента из трёх слов до и трёх слов после выбранного.
3. Проверить на desktop и touch-устройстве выделение слова, добавление в личный
   словарь и подсветку в тексте.
4. Зафиксировать отдельно ограничения старых данных: книги, импортированные до
   исправления ресурсов EPUB, нужно переимпортировать для показа иллюстраций.

Критерий готовности: есть короткий ручной чек-лист с результатами; проблемы
попадают в конкретный следующий этап, а не маскируются редизайном.

## 1. Библиотека: обложки книг — выполнено

Цель: на карточке готовой книги показывается извлечённая обложка, а не буква
заголовка.

1. Проверить EPUB2-метаданные `meta name="cover"`, EPUB3 `cover-image` и
   fallback-случаи на реальных EPUB.
2. Для уже загруженных книг добавить безопасный путь переобработки оригинального
   EPUB: повторно извлечь обложку и HTML глав без повторной загрузки файла.
3. Показать понятный fallback, когда в EPUB действительно нет обложки.
4. Добавить тесты EPUB2/EPUB3 и HTTP-загрузки обложки с access token.

Критерий готовности: новая и переобработанная книга с валидной PNG/JPEG/GIF/WebP
обложкой показывает её в общем и личном каталогах; книга без обложки не даёт
ошибку и показывает fallback.

## 2. Ридер: настраиваемый цвет подсветки — выполнено

Цель: каждый пользователь выбирает цвет, которым отмечаются только слова из
его личного словаря.

1. Согласовать компактный фиксированный набор доступных цветов: рекомендовано
   4–6 контрастных вариантов вместо произвольного HEX-ввода.
2. Добавить миграцию PostgreSQL: `user_reader_settings.highlight_color` с
   безопасным значением по умолчанию `amber`.
3. Расширить domain, proto `ReaderSettings`, use case и gRPC handlers получения
   и сохранения настроек; валидация принимает только согласованные значения.
4. Добавить selector цвета в существующие «Настройки текста» с мгновенным
   preview и явной кнопкой сохранения.
5. Передавать цвет через CSS custom property, не изменяя HTML EPUB и не создавая
   style-атрибуты в пользовательском тексте.
6. Добавить unit-тесты валидации, repository/integration-тест миграции и
   frontend-тест preview/сохранения.

Критерий готовности: после обновления страницы выбранный цвет сохраняется для
текущего пользователя и применяется ко всем его подсвеченным словам; настройки
другого пользователя не меняются.

## 3. Встроенный переводчик: доведение сценария — выполнено

Цель: выделение одного английского слова на desktop или touch сразу открывает
доступную карточку со словарными данными и переводом контекста.

1. Закрыть морфологический слой: исходная форма проверяется первой, затем
   неправильные и регулярные формы; кандидат выбирается только если он есть в
   локальном словаре.
2. Отображать все возвращённые senses: часть речи, все русские переводы,
   английский и, когда доступен, русский пример.
3. Сохранять в личный словарь выбранный sense; проверить, что он возвращается с
   переводом и примером на странице «Мой словарь».
4. Формировать отдельный контекстный фрагмент: три слова перед выбранным,
   выбранное слово и три слова после него. Переводить и показывать только его,
   а не целое предложение; у начала и конца текста фрагмент будет короче.
   При недоступном LibreTranslate показать понятное состояние, не скрывая
   словарные senses.
5. Добавить UI-тесты для loading, empty dictionary, provider error и формы
   `putting`, `hummed`, `took`, `got`.

Критерий готовности: для слова с несколькими смыслами видны все смыслы и
примеры; для отсутствующего в dump слова не появляется ложный пустой sense, но
перевод контекстного фрагмента остаётся доступен.

## 4. Точечная правка текста каталога — выполнено

Цель: убрать фразу «EPUB-книги, доступные всем членам семьи.» из общего
каталога, не меняя остальную навигацию и доступность.

1. Удалить только указанную строку.
2. Проверить заголовочную иерархию, пустой каталог, загрузку EPUB и mobile
   layout.

Критерий готовности: строки нет ни в desktop, ни в mobile интерфейсе; другие
тексты и состояния каталога сохранены.

## 5. Редизайн интерфейса — ожидает консультации с владельцем

Требование прямо запрещает начинать визуальные изменения без консультации.
До согласования допустимы только исправления поведения из этапов 0–4.

На консультации нужно выбрать:

1. настроение интерфейса: книжное/тёплое, нейтральное/минималистичное или
   другое;
2. 2–3 референса сайтов или приложений, которые нравятся;
3. приоритет desktop/mobile и желаемую плотность информации;
4. допустимость новых иллюстраций, текстур и анимаций.

После ответа будет подготовлен маленький визуальный прототип каталога и
ридера. Его утверждение — обязательный критерий начала реализации CSS/UI.

## 6. Итоговая проверка и документация — не начато

1. Прогнать `go test ./...`, `npm run lint`, `npm run build` и проверку
   форматирования.
2. Добавить Playwright-сценарий: login → загрузка EPUB с обложкой → открытие →
   настройка цвета → перевод формы глагола → добавление в словарь → подсветка →
   повторное открытие на сохранённой позиции.
3. Обновить оба README, только если изменятся команды, порты, переменные
   окружения или интеграция frontend/backend.
4. Записать результат ручной проверки на desktop и touch.

Критерий готовности: все автоматические проверки зелёные, пользовательский
сценарий проходит без ручного вмешательства в БД или конфигурацию.
