## 1. Адаптер синтезатора

1. Создать `frontend/src/features/reader/speechSynthesis.ts` с узким
   интерфейсом: `supported`, `voices`, `speak`, `cancel`, `isSpeaking`.
2. Изолировать обращения к `window`, подписаться на `voiceschanged`,
   нормализовать текст, выбрать fallback-голос и разбивать длинный текст до
   1 200 символов по предложениям.
3. Очищать состояние на `end`, `error` и `cancel`; не логировать текст книги.

Критерий: адаптер не обращается к backend и корректно отменяет очередь.

## 2. Интерфейс ридера

1. В словарной карточке добавить «Слушать» и выбор «Слово / Контекст /
   Предложение».
2. По нажатию запустить адаптер с `lang='en-US'`, показать «Остановить» и не
   допустить параллельных голосов.
3. Отменять воспроизведение при закрытии карточки, смене главы и уходе со
   страницы; показать доступное состояние без голоса.

Критерий: каждый из трёх текстов запускается явно и останавливается безопасно.

## 3. Настройки

1. Добавить в `ReaderSettings` `tts_voice_uri` и `tts_rate`; миграцию и
   валидацию скорости `0.6..1.2`.
2. В «Настройках текста» показать доступные английские голоса и регулятор
   скорости; при исчезнувшем голосе использовать fallback.
3. Сохранять только персональные настройки, не аудио и не текст книги.

Критерий: голос и скорость переживают обновление страницы.

## 4. Проверка и приёмка

1. Unit-тесты: отсутствующий API, асинхронные голоса, fallback, разбиение,
   остановка и ошибка.
2. Тесты `ReaderPage`: правильный источник текста, остановка при закрытии и
   смене главы, состояние без голоса.
3. Ручная проверка Chrome, Safari и Firefox на desktop и mobile, в том числе
   без сети и при быстрых повторных нажатиях.
4. Запустить `npm run lint`, `npm run test`, `npm run build`, `go test ./...`
   и удостовериться, что TTS не создаёт API-запросов или логов с текстом.
