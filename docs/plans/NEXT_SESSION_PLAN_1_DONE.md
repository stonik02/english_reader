# План следующих доработок: книги

Дата подготовки: 2026-09-04.

Этот план объединяет связанные изменения backend и frontend. Выполнять пункты
нужно по порядку: сначала восстановить корректное действие уже загруженной
книги, затем расширить модель обложкой и только после этого добавить удаление.

## 1. Исправить отображение статуса `READY`

**Статус:** `[x]` выполнено 2026-09-04.

### Что происходит сейчас

В PostgreSQL и gRPC backend передаёт статус строчными буквами (`ready`,
`processing`, `failed`). Frontend-карточка сравнивает значение с `READY` и
поэтому ошибочно показывает «Чтение станет доступно после обработки» даже для
готовой книги.

### Backend

- Зафиксировать единый публичный формат статусов в контракте: либо нижний
  регистр (`ready`), либо верхний (`READY`).
- Добавить тест gRPC-ответа каталога для каждого статуса.

### Frontend

- Нормализовать статус перед сравнением и перед выводом подписи.
- Показывать отдельный понятный текст для `failed`: файл не прошёл обработку,
  а не «ожидает обработки».
- Добавить тест карточки: `ready` отображает кнопку «Читать».

**Готово, когда:** карточка книги Harry Potter со статусом `ready` показывает
«Готова к чтению» и активную кнопку «Читать».

## 2. Сохранять и показывать обложки EPUB

**Статус:** `[x]` выполнено 2026-09-04.

### Backend

- При обработке EPUB находить изображение обложки по стандартным метаданным
  OPF (EPUB 2 и EPUB 3), а не по имени файла.
- Проверять MIME-тип и размер изображения; сохранять безопасный файл рядом с
  исходным EPUB в storage книги.
- Добавить миграцию для пути/идентификатора обложки и включить его в модель
  `Book` и gRPC-контракт.
- Отдать обложку через защищённый HTTP endpoint либо через URL, доступный всем
  авторизованным членам семьи.
- Добавить тесты: EPUB с обложкой, EPUB без обложки и недопустимое изображение.

### Frontend

- Добавить `cover_url` в тип книги и показать изображение в карточке.
- Оставить буквенную заглушку, если в EPUB нет обложки или изображение не
  загрузилось.
- Добавить доступный `alt` с названием книги.

**Готово, когда:** обложка из EPUB отображается в каталоге после статуса
`ready`, а у книги без обложки остаётся аккуратная заглушка.

## 3. Удалять книгу из общего каталога для всех пользователей

**Статус:** `[x]` выполнено 2026-09-04.

### Правило продукта

Удаление глобальное и необратимое: книга исчезает из общего каталога и личных
библиотек всех членов семьи. Действие доступно каждому авторизованному
пользователю семейного приложения, как было запрошено.

### Backend

- Добавить авторизованный endpoint/гRPC-метод удаления книги.
- В одной транзакции удалить запись книги, главы, job обработки и связи
  `user_books`; удаление должно быть идемпотентным или возвращать понятный
  `not found`.
- После успешной транзакции удалить исходный EPUB и сохранённую обложку из
  файлового storage; при сбое не оставлять доступный «осиротевший» файл.
- Добавить тесты прав доступа, каскадного удаления и удаления книги во время
  обработки.

### Frontend

- Добавить кнопку «Удалить книгу» в карточку общего каталога.
- Перед удалением открывать диалог подтверждения с названием книги и явным
  предупреждением, что она исчезнет у всех.
- На время запроса блокировать повторный клик, после успеха удалить карточку
  из кеша каталога и личной библиотеки; при ошибке показать сообщение и кнопку
  повторной попытки.

**Готово, когда:** любой вошедший пользователь подтверждает удаление, книга и
все её пользовательские связи исчезают, а файл и обложка очищаются на backend.

## Порядок проверки в конце работы

1. Backend: миграции, `go test ./...`, `go vet ./...`.
2. Frontend: `npm run lint`, `npm run build`, `npm run format:check`.
3. В браузере: загрузить EPUB с обложкой → дождаться `ready` → открыть
   читалку → удалить книгу из другого пользователя → убедиться, что она
   исчезла у обоих.
