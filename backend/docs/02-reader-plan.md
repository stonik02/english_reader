# Backend-план: EPUB-ридер

## Цель и границы

Backend должен позволить открыть готовый EPUB на последней позиции, получить
содержимое соседних глав, сохранить продвижение и настройки чтения. Формат
только EPUB: сервер не создаёт PDF-страницы. Экранные страницы формирует
frontend из XHTML с учётом размера шрифта и viewport; backend хранит устойчивые
EPUB CFI-якоря.

В MVP отсутствуют offline-копии, синхронизация с ручным разрешением конфликтов,
заметки, закладки и DRM EPUB.

## Сценарии и правила

| Сценарий | Правило backend |
| --- | --- |
| Открыть книгу впервые | Проверить `READY`, вызвать `EnsureBookInMyLibrary(first_read)`, вернуть начало первой главы. |
| Открыть повторно | Вернуть сохранённый `epub_cfi`; если глава после повторной обработки недоступна, вернуть начало ближайшей доступной главы. |
| Следующая/предыдущая «страница» | Frontend листает внутри XHTML сам. При CFI за границей главы он запрашивает нужную главу по spine sequence/href. |
| Изменить шрифт | Сохранить личную настройку 80–200%; CFI не пересчитывается и прогресс не сбрасывается. |
| Сохранить позицию | Принимать CFI, chapter и процент с `revision`. Более старая revision не перезаписывает новую. |
| Удалить книгу из моей библиотеки | Следующий запрос чтения снова добавит книгу по правилу первого чтения; такое поведение показывается frontend. |

Сервер не принимает HTML, CFI или chapter id на доверие: chapter должен
принадлежать запрошенной книге, CFI должен иметь допустимую длину и формат,
процент — быть в диапазоне 0..100.

## Данные и инварианты

```text
books ──< book_chapters (sequence, href, start_cfi, end_cfi, sanitized_html)
users ──< user_books >── books
user_books ──< reading_progress (одна позиция на пользователя и книгу)
users ──1 user_reader_settings
```

Миграции раздела:

- `reading_progress`: `(user_id, book_id)` PK и FK на `user_books`, `chapter_id`,
  `epub_cfi`, `progress_percent`, `revision`, `updated_at`;
- `user_reader_settings`: `user_id PK`, `font_scale CHECK 80..200`, `theme`,
  `line_height`, `updated_at`;
- индекс `book_chapters(book_id, sequence)` для перехода между главами.

`SaveReadingProgress` выполняется условным update: новая позиция применяется
только когда `request.revision > stored.revision` (или запись отсутствует).
Ответ всегда содержит актуальную серверную revision — так клиент может
восстановиться после гонки между двумя вкладками/устройствами.

## gRPC-контракт

| Метод | Назначение |
| --- | --- |
| `GetReadingState(book_id)` | Добавляет книгу в личную библиотеку при необходимости и возвращает locator, chapter summary, настройки и статус. |
| `GetChapter(book_id, chapter_id|href)` | Возвращает только подготовленную XHTML-главу, CFI-границы, sequence и ссылки на разрешённые ресурсы. |
| `GetAdjacentChapter(book_id, chapter_id, direction)` | Возвращает metadata следующей/предыдущей главы; может быть объединён с `GetChapter` в реализации. |
| `SaveReadingProgress(book_id, chapter_id, epub_cfi, percent, revision)` | Идемпотентно сохраняет более новую позицию и выдаёт актуальную запись. |
| `GetReaderSettings()` / `UpdateReaderSettings(...)` | Читает и валидирует личные параметры отображения. |

Любой метод требует JWT. Каталожная книга доступна членам семьи, но прогресс и
настройки выбираются только по `subject` токена — клиент не передаёт `user_id`.
`GetChapter` отвечает `FAILED_PRECONDITION` для неготовой книги и `NOT_FOUND`
для неизвестной chapter/книги.

7. Добавить OpenTelemetry spans и метрики задержки `GetChapter`, ошибок CFI и
   времени подготовки главы без записи текста книги в логи.

## Definition of Done

- После сохранения CFI пользователь открывает ту же книгу с этой позиции.
- Изменение шрифта не изменяет CFI и не создаёт новую запись progress.
- Backend выдаёт только главы запрошенной готовой книги, не исходный EPUB.
- Старая revision не может перетереть новую позицию, а личный прогресс одного
  аккаунта не виден другому.
