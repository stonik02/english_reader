# Backend-план: личный словарь и подсветка

## Цель и границы

Раздел реализует личный словарь: сохранить слово из карточки перевода, показать
свой список и пометить известные пользователю слова в тексте читаемой книги.
Словарь не общий: одно и то же lemma разные члены семьи добавляют независимо.
В MVP нет интервальных повторений, карточек, статистики, совместных списков и
ручного редактирования словарных senses.

## Сценарии и правила

| Сценарий | Правило backend |
| --- | --- |
| Нажатие `+` | `SaveEntry` принимает lemma и опциональный выбранный sense. Создаёт запись только для subject JWT; повторное сохранение идемпотентно. |
| Слово уже в словаре | Ответ содержит `already_saved = true`; frontend показывает это вместо второй записи. |
| Показ списка | `ListEntries` выдаёт только записи текущего пользователя, с cursor pagination, поиском по lemma и выбранным переводом. |
| Удаление | `DeleteEntry` удаляет только связь пользователя с lemma, не словарный source и не записи других аккаунтов. |
| Открытие главы | `GetHighlights` выдаёт набор нормализованных lemmas текущего пользователя, которые встречаются в указанной главе. |
| Подсветка формы слова | Совпадение выполняется по lemma, если у токена известна лемматизация; иначе допустимо exact normalised match с явным флагом fallback. |

Добавить можно только lemma из локального `dictionary_lemmas`, полученный
`LookupWord`; клиент не передаёт свободный `user_id`. Это исключает разрастание
несогласованных вариантов (`run`, `Run`, `running`) и позволяет использовать
одну нормализацию для карточки и подсветки.

## Данные и инварианты

```text
users ──< vocabulary_entries >── dictionary_lemmas ──< dictionary_senses
                                   ^
                                   └── book_chapter_tokens (опциональный индекс)
```

Миграции:

- `vocabulary_entries`: UUID, `user_id FK`, `lemma_id FK`,
  `chosen_sense_id FK NULL`, `source_form`, timestamps,
  `UNIQUE(user_id, lemma_id)`;
- проверка, что `chosen_sense_id` принадлежит тому же lemma, выполняется use
  case либо составным FK;
- на первом этапе `book_chapter_tokens` не обязателен: глава токенизируется из
  `plain_text` при подготовке/чтении. При замере медленной подсветки добавляется
  таблица `(chapter_id, normalized_token, lemma_id, positions)` и индекс по
  `(chapter_id, lemma_id)`.

Уникальное ограничение является последней линией защиты от двойного клика и
гонки двух устройств. В ответ на conflict repository читает существующую запись
и возвращает её как успешный idempotent result.

## Подсветка без утечки данных

`GetHighlights(book_id, chapter_id)` сначала проверяет готовность книги и
принадлежность chapter. Затем выбирает только lemmas текущего пользователя,
которые реально присутствуют в главе. Ответ не содержит полный словарь
пользователя, записи других членов семьи или HTML главы.

Для маленького семейного каталога допустим простой вариант: запросить lemmas
пользователя, токенизировать `plain_text` сервера и вернуть пересечение. Если
книг/словарей станет больше, включается `book_chapter_tokens`, подготовленный
в ingestion job. Контракт RPC при этом не меняется.

Frontend подсвечивает text nodes по возвращённым lemma/позициям. Backend не
вставляет `<mark>` в XHTML и не меняет оригинальную главу: так один пользователь
не увидит подсветку другого и кэш подготовленного EPUB остаётся общим.

## gRPC-контракт

| Метод | Назначение |
| --- | --- |
| `SaveEntry(lemma_id, chosen_sense_id?, source_form, idempotency_key)` | Создаёт/возвращает личную запись. |
| `ListEntries(cursor, limit, query?)` | Личный paginated vocabulary со смыслом для отображения. |
| `DeleteEntry(entry_id|lemma_id)` | Идемпотентно удаляет личную запись. |
| `GetHighlights(book_id, chapter_id)` | Возвращает `repeated HighlightToken { lemma_id, lemma, positions?, match_kind }`. |

`SaveEntry` отвечает `INVALID_ARGUMENT` для invalid sense/lemma pair и
`NOT_FOUND` для несуществующей lemma. `GetHighlights` не требует отдельного
добавления книги: запрос чтения уже выполнил `EnsureBookInMyLibrary`; но он
требует `READY` и возвращает `FAILED_PRECONDITION` иначе.

## План работ

1. Описать vocabulary/highlight proto messages и сгенерировать код.
2. Создать миграцию `vocabulary_entries`, индексы и repository с UPSERT.
3. Реализовать `SaveEntry`, `ListEntries`, `DeleteEntry` с JWT subject и
   cursor pagination; добавить авторизационные unit-тесты.
4. Вынести общий normalizer/tokenizer из translator module, чтобы карточка и
   подсветка одинаково обрабатывали регистр, пунктуацию и apostrophe.
5. Реализовать простой `GetHighlights` через `plain_text` и набор lemma;
   добавить лимиты на главу/количество слов в ответе.
6. При необходимости, измеренной профилированием, добавить
   `book_chapter_tokens` в ingestion pipeline без изменения RPC.
7. Добавить интеграционные тесты: два пользователя с разными словарями,
   повторное `SaveEntry`, удаление и подсветка нескольких форм одного lemma.

## Definition of Done

- Сохранённое слово видно только в словаре и подсветке добавившего его аккаунта.
- Повторное добавление не создаёт дубль и не меняет выбранный sense без явного
  будущего метода обновления.
- `GetHighlights` возвращает только слова текущей главы и не модифицирует
  сохранённый XHTML.
- Карточка перевода может сразу сообщить UI, что lemma уже сохранена.
