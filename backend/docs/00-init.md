# План инициализации backend

Статус: реализовано и проверено в Docker Compose.

## Цель первого технического этапа

Получить воспроизводимый Go 1.25 backend-каркас, который запускается локально
в Docker и содержит безопасные точки расширения для модулей библиотеки, ридера,
переводчика и словаря. На этом этапе не реализуются пользовательские сценарии
целиком: создаётся инфраструктура, миграции и контрактная основа.

## План работ

1. [x] Создать модуль Go, структуру Clean Architecture и единый конфигурационный
   слой на переменных окружения.
2. [x] Добавить PostgreSQL через `pgxpool`, health/readiness checks, миграции и
   начальную транзакционную схему данных.
3. [x] Поднять gRPC-сервер с health и reflection, HTTP-служебный сервер с удобным
   роутером `chi`, структурированные логи и корректное завершение процесса.
4. [x] Добавить Dockerfile, Compose для PostgreSQL, LibreTranslate, Envoy и
   persistent volume книг; внешний доступ оставлять только у Envoy/frontend.
5. [x] Добавить Makefile: запуск/остановка инфраструктуры, миграции, тесты,
   линт/форматирование, генерация proto и просмотр логов.
6. [x] Написать unit-тесты конфигурации и readiness, проверить компиляцию.
   `go test ./...` выполнен успешно. Локальная команда `go version` сообщает
  Go 1.23.4; Dockerfile закреплён на Go 1.25, а контейнерная сборка API
  выполнена успешно.
7. [x] Реализовать AuthService: Argon2id, PostgreSQL-сессии с refresh-token
   rotation/revocation, JWT access token, HTTP Swagger и сгенерированный gRPC
   контракт.

## Результат этапа

- `make infra-up` поднимает Postgres и LibreTranslate; PostgreSQL использует
  порт `5433` по умолчанию, чтобы не конфликтовать с локальной базой на `5432`.
- Envoy публикует gRPC-Web на `8082` по умолчанию; `8080` оставлен свободным
  для других локальных проектов.
- `make migrate-up` применяет схему PostgreSQL.
- `make run` запускает API локально; `make test` запускает unit-тесты.
- gRPC доступен внутри сети на `:9090`, gRPC-Web — через Envoy `:8082`,
  HTTP API и Swagger в development — на `:8083`.
- Следующим этапом реализуется `LibraryService` согласно
  [плану библиотеки](01-library-plan.md).
