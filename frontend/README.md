# English Reader — frontend

Веб-интерфейс закрытого семейного EPUB-ридера. Здесь будут библиотека книг,
ридер, перевод выделенных слов и личный словарь.

## Технологии

- **React** — строит интерфейс из небольших переиспользуемых компонентов.
- **TypeScript** — добавляет проверку типов, чтобы раньше находить ошибки.
- **Vite** — запускает приложение во время разработки и собирает оптимизированную
  версию для публикации.
- **ESLint** и **Prettier** — автоматически поддерживают единый стиль и помогают
  не допускать типичных ошибок.
- **TanStack Query** — хранит и обновляет данные, полученные от backend.
- **gRPC-Web через Envoy** — типизированная связь браузера с Go API.

React Router отвечает за переходы между экранами. TypeScript gRPC-Web-клиенты
генерируются из исходных `.proto` контрактов — отдельные вручную написанные
типы API не нужны. Их JavaScript-часть использует формат CommonJS; она
подключена как локальная npm-зависимость, поэтому Vite автоматически
предсобирает её в понятный браузеру код во время локальной разработки.

## Требования

- Node.js 22.11 или новее;
- npm 10 или новее.

Проверить установленные версии можно так:

```bash
node --version
npm --version
```

## Первый запуск локально

Выполните из корня репозитория:

```bash
cd frontend
npm install
npm run dev
```

Vite выведет адрес приложения. По умолчанию это
[`http://localhost:5173`](http://localhost:5173). Пока команда запущена, она
следит за изменениями файлов и автоматически обновляет страницу в браузере.
Остановить её можно сочетанием `Ctrl+C` в том же терминале.

После первого запуска вместо `npm install` используйте `npm ci`: эта команда
восстанавливает версии строго из `package-lock.json`.

## Настройка адреса backend

По умолчанию frontend обращается к Envoy по `http://localhost:8082`, а к HTTP
API для регистрации, входа и refresh-cookie — по `http://localhost:8083`. Это
подходит для локального запуска backend из корневого README.

Чтобы использовать другой gateway, скопируйте пример и замените адрес:

```bash
cd frontend
cp .env.example .env.local
```

В `.env.local` при необходимости измените `VITE_GRPC_WEB_URL` и
`VITE_HTTP_API_URL`. Файл `.env.local` не попадает в Git; не храните в нём
токены или пароли.

## Генерация API-клиентов

Контракты находятся в `../protos/reader/v1`. После изменения `.proto` файлов
выполните:

```bash
cd frontend
npm run generate:api
```

Команда обновит `src/api/gen/`. Эти файлы создаются автоматически и не должны
редактироваться вручную. Для генерации требуется `protoc`; на macOS его можно
установить командой `brew install protobuf`. Сами плагины генерации уже
зафиксированы в `package-lock.json`.

## Полезные команды

| Команда                | Назначение                                                  |
| ---------------------- | ----------------------------------------------------------- |
| `npm run dev`          | Запустить frontend для разработки.                          |
| `npm run generate:api` | Пересоздать gRPC-Web-клиенты из `../protos`.                |
| `npm run lint`         | Проверить код ESLint.                                       |
| `npm run format:check` | Проверить форматирование.                                   |
| `npm run format`       | Исправить форматирование автоматически.                     |
| `npm run build`        | Проверить TypeScript и собрать production-версию в `dist/`. |
| `npm run preview`      | Открыть локально уже собранную production-версию.           |

## Структура

```text
src/
  app/          # запуск приложения, маршруты и глобальные стили
  api/          # generated gRPC-клиенты, API-функции и общий API-клиент
  features/     # самостоятельные части: auth, library, reader, dictionary
  pages/        # страницы приложения
  shared/       # общие UI-компоненты и утилиты
docs/           # карта экранов и план разработки
```

Подробная карта интерфейса находится в [docs/SCREENS.md](docs/SCREENS.md), а
текущий прогресс — в [docs/IMPLEMENTATION_PLAN.md](docs/IMPLEMENTATION_PLAN.md).

## Связь с backend

Backend запускается отдельно: инструкция для совместного запуска находится в
[корневом README](../README.md). Его Envoy gateway доступен по
`http://localhost:8082`; он уже разрешает браузерные запросы с локальных
Vite-адресов `http://localhost:5173` и `http://localhost:5174`.

Для production-версии frontend не загружается вручную: серверная команда
`docker compose --env-file .env up --build -d` пересобирает его вместе с
остальными контейнерами. Полный порядок обновления GitHub → сервер приведён в
[инструкции production-развёртывания](../deploy/production/README.md#updating-the-deployed-application).

На странице «Общий каталог» frontend получает реальные книги через gRPC-Web,
показывает их статусы и умеет подгружать следующую страницу. Готовую книгу
можно добавить в личную библиотеку. Кнопка «Загрузить EPUB» открывает окно
выбора или перетаскивания файла: принимаются `.epub` размером до 50 МБ, а
реальный прогресс отправки показывается до появления книги в каталоге со
статусом подготовки.

Ридер получает XHTML-главы, сохраняет позицию и настройки через gRPC-Web.
Каждое читаемое слово в главе — интерактивный элемент: при наведении оно слегка
подсвечивается, а одно нажатие сразу показывает словарную карточку. Перевод
короткого контекста загружается в этой карточке отдельно; полное предложение
переводится только по явной кнопке. Если выделить два и более слова, появляется
кнопка «Перевести выделенное». После перевода слово можно добавить в личный
словарь; страница «Словарь» поддерживает поиск, постраничный просмотр и
удаление. Сохранённые слова сервер возвращает как позиции, а frontend безопасно
подсвечивает их только в text nodes текущей главы.

Регистрация, вход и обновление сессии используют HTTP API только для того,
чтобы backend мог хранить refresh token в `HttpOnly` cookie. JavaScript его не
читает и не сохраняет; access token хранится лишь в памяти страницы. Остальные
API-вызовы продолжают идти через gRPC-Web/Envoy.

Загрузка EPUB — исключение: browser gRPC-Web не поддерживает client-streaming,
поэтому файл отправляется в HTTP API как `multipart/form-data` на
`POST /api/v1/library/books` с тем же access token.
