проверку TypeScript, ESLint, Prettier и базовые команды разработки. Создать

**Результат для вас:** локально открывается пока пустая, но настоящая страница
приложения; вы узнаете, что такое frontend-проект, dev-сервер и сборка.

**Готово, когда:** `npm run dev`, `npm run build` и проверка кода выполняются
без ошибок.

**Итог (2026-09-03):** создан проект React + TypeScript + Vite, настроены
ESLint и Prettier, добавлена стартовая страница и структура папок. Проверены
`npm run dev`, `npm run lint`, `npm run build` и `npm run format:check`.

### 3. Подключение к backend API `[x]`

Настроить Envoy/gRPC-Web, генерацию TypeScript-клиентов из `../protos`, общий
клиент API, TanStack Query и единое отображение ошибок. Сгенерированный код не

**Результат для вас:** frontend может безопасно запрашивать реальные данные у
backend, а не использовать тестовые заглушки.

**Готово, когда:** генерация повторяется одной командой, а тестовый запрос к
backend проходит через Envoy.

**Итог (2026-09-03):** добавлены TanStack Query, gRPC-Web runtime и генерация
клиентов из `../protos` командой `npm run generate:api`. Настроены общий адрес
Envoy, хранение access token только в памяти, метаданные авторизации и единое
преобразование gRPC-ошибок в понятные сообщения. Экран общего каталога делает
реальный `ListCatalog` запрос и показывает его статус. Проверены генерация,
`npm run lint`, `npm run build`, `npm run format:check` и бинарный gRPC-Web
запрос через Envoy (`grpc-status: 0`).

### 4. Сессия: регистрация, вход и выход `[x]`

Сделать страницы входа/регистрации, проверки форм, хранение сессии, обновление
access token и защиту закрытых страниц.

**Результат для вас:** каждый член семьи входит в свой профиль и видит только
свои личные данные.

**Готово, когда:** можно зарегистрироваться, войти, выйти и открыть сессию
заново без ручной работы с токенами.

**Итог (2026-09-03):** формы регистрации и входа подключены к HTTP Auth API.
Refresh token остаётся в `HttpOnly` cookie; access token хранится только в
памяти. При запуске клиент пытается обновить сессию и запрашивает текущего
пользователя, а gRPC `UNAUTHENTICATED` один раз запускает обновление и повтор
вызова. Закрытые страницы защищены route guard, добавлен выход. Для cookie
сессии backend получил ограниченный credentialed CORS по `FRONTEND_ORIGIN`.
Проверены CORS preflight, безопасный `401` без cookie, Go-пакеты, frontend
lint/build/format.

**Готово, когда:** изменение статуса и добавление книги корректно отражаются

**Итог (2026-09-03):** общий каталог получает книги через gRPC-Web с

в личную библиотеку; после успеха кнопка меняется без перезагрузки страницы.
Проверены `npm run lint`, `npm run build` и `npm run format:check`.

### 6. Загрузка EPUB `[x]`

Сделать модальное окно выбора файла, проверки `.epub`, отображения прогресса и
отправку через согласованный HTTP multipart endpoint.

**Готово, когда:** загруженный EPUB появляется в общем каталоге со статусом
обработки, а ошибки файла понятны пользователю.

**Итог (2026-09-03):** добавлено доступное модальное окно с выбором или
перетаскиванием файла, проверкой расширения, пустого файла и лимита 50 МБ.
Загрузка идёт через HTTP multipart `POST /api/v1/library/books` с реальным
процентом отправки, access token и единичным обновлением сессии при `401`.
После `201 Created` каталог обновляется, а пользователь видит, что книга
подготавливается. Проверены `npm run lint`, `npm run build` и
`npm run format:check`.

**Результат для вас:** можно реально читать EPUB и закрыть браузер, не теряя

**Итог (2026-09-04):** экран подключён к `GetReadingState` и
`GetAdjacentChapter`, отображает подготовленную и санитизированную главу,
открывает сохранённую главу и листает между главами. Backend уже автоматически
добавляет готовую книгу в личную библиотеку при первом открытии. Для выбранного
XHTML-ридера вместо EPUB.js сохранена относительная позиция прокрутки на главу:
она восстанавливается после закрытия браузера и при изменении размера текста.
